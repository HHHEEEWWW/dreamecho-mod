### 1.3 词缀 T 级机制（关键）
- 配置表：`ConceptMemoryAffix`（Id / **Level(T级)** / MaxLevel / MutexGroup(互斥组) / AffixType / Weight / AttrMin / AttrMax / Cost）
- 词缀包：`ConceptMemoryAffixPack`（Id / AffixType / WeightPack / PackMinLevel / AffixList / AffixTag）
- 装备基底：`ConceptMemoryBase`（BaseName / BaseAffixId / RandomAffixGroup / **MaxPrefixNum / MaxSuffixNum**）
- 查询：`TConceptMemoryAffix.Get(id, level)` —— **T 档由 level 决定**
- 实测档位（affix_browser-cn.html）：**T1 最强**（需求 81，+115%~131%，权重 25）→ T7 最弱（需求 1，+9%~26%，权重 600）

### 1.4 掉落链路（关键方法，`Echoes.Core.Utility.DropHelper`）
```
GetDrop(packId, stage, out rarity, dropLevel, excluded, mustDrop)  稀有度+条目选择
  └ RandomDrop(weights, luckType, rarityIndexList)                 权重掷骰
CreateDrop(packIdList, position, dropRatio)                        ← 生成掉落物，dropRatio=数量倍率
GetExtraDropRatioByLuckType(drop, memoryRatio, cointRatio, shardRatio) ← 三材料比率
BuildMemoryRandom(affixPacks, packWights, memoryLevel, minLevel, excluded, mutexGroups) ← 词缀包权重掷骰
BuildMemory(drop, memoryLevel, mustTargetList, mustAddAffix)       ← 原生支持"必加词缀"
BuildMemoryAttr(affix, type, max)                                  ← max=true 满 roll
```
- `EDropLuckyType`：NoLuckyChange / NormalLuckyChange / MemoryLuckyChange / HpBallLuckyChange / SpBallLuckyChange / MemoryLuckyChangePartialExtraDrop
- `Drop`（配置表）：DropPack / DropType / DropContentId / **Rarity** / RankRange / DropLevelLimit / **Weight** / Cost / NeedDropTag / ConditionId

## 2. 目标可行性

### 目标 1：碎片 10 倍掉落（含构成平衡）— ✅ 高可行
- 切入点 A：`CreateDrop(packIdList, position, dropRatio)` → dropRatio ×N（通用数量倍率）
- 切入点 B：`GetExtraDropRatioByLuckType(drop, memoryRatio, cointRatio, shardRatio)` → 按材料类型精确放大（**推荐**：可只放大 shard 比率，或三比率按构成比例同步放大）
- 构成平衡：三比率同倍数放大可保持构成不变；或按观察到的真实构成比例分别设定倍数
- ⚠️ 需运行时确认：哪个掉落包是 Shard（`EConceptType.Shard`）、基础比率值、`GenralDrop.LuckType` 分支

### 目标 2：只出最高 T（T1）词缀 — ✅ 高可行
- 切入点：Hook `TConceptMemoryAffix.Get(id, level)` → 强制 level ≥ 81（或 MaxLevel）
- 或 Hook `BuildMemoryRandom(...)` 的 memoryLevel/minLevel 参数
- 效果：新掉落/新生成装备的词缀全部 T1 档；已存在装备不受影响
- 需确认：游戏中 Memory 生成时的实际 level 传递路径（运行时观察）

### 目标 3：自选词缀（规则内）— 暂缓（用户决定）
- 机制支持：`BuildMemory(..., mustAddAffix)` + `MutexGroup` 互斥 + `MaxPrefixNum/MaxSuffixNum` 上限
- 待目标 1+2 完成后评估

## 3. 实现方案

**技术**：BepInEx 6 IL2CPP + HarmonyX（BepInEx 内置，IL2CPP 静态方法 Patch 标准做法）

**阶段划分**：
1. **观察阶段（先做）**：探针插件 Hook 上述方法，仅打印参数（packId/dropRatio/比率/level/rarity），用户正常游玩一次，从日志确认：货币对应关系、碎片掉落路径、词缀 level 实际值、掉落构成比例
2. **实现阶段**：根据观察结果实现目标 1（碎片 10 倍 + 构成平衡）与目标 2（T1 词缀），逐项游戏内实测
3. **配置化**：倍数、词缀相关开关做成 BepInEx 配置文件，便于调整

## 4. 风险

| 风险 | 应对 |
|---|---|
| IL2CPP 方法 Patch 兼容性 | 先做冒烟测试（探针插件即冒烟测试） |
| 参数 byref/泛型签名复杂 | 按实际签名适配；选签名简单的切入点 |
| 游戏更新改配置 ID | 插件配置化 + 重新导出词缀清单 |
| 碎片 10 倍导致物品堆积/性能 | 观察实际掉率后定倍数；可加数量上限 |
